# Маркетинг: позиционирование, лендинг и рост GitHub (KPI, без спама)

Канонический артефакт для задачи вида «лендинг + измеримый рост org **getskillpack**». Согласование формулировок — board; реализация лендинга и UI — Founding Engineers по подзадачам в Paperclip (без лишних @-heartbeat: достаточно назначения и чёткого ТЗ в описании тикета).

## 1. Позиционирование (кратко)

| Сущность | Одна фраза | Для кого |
|----------|------------|----------|
| **getskillpack** (org / экосистема) | Открытая экосистема для **поиска, версионирования и установки skills** для агентов и IDE — как «пакетный менеджер» для навыков. | Создатели skills, команды с AI-агентами, интеграторы. |
| **registry** ([`getskillpack/registry`](https://github.com/getskillpack/registry)) | HTTP API и хранилище метаданных/артефактов skills; контракт совместимости версий. | Разработчики CLI, CI, сервисов. |
| **skillget** (CLI, [`getskillpack/cli`](https://github.com/getskillpack/cli)) | Официальный клиент командной строки: `search`, `install`, `config`, lockfile — точка входа для разработчика. | Пользователи репозиториев и CI. |
| **skillget-manager** | Ядро установки (lockfile, загрузка, слияние) — библиотека/пакет под CLI. | Мейнтейнеры продукта. |

**Не смешивать в публичных текстах:** «skpkg» как внутреннее/историческое имя workspace и «skillget» как пользовательское имя CLI — в README и лендинге приоритет **skillget** + **getskillpack**.

**Ценность в одном абзаце (черновик для hero):**  
Установите проверенный skill одной командой, зафиксируйте версию в репозитории и воспроизводите окружение для команды и агентов — без копирования zip и ручных инструкций.

## 2. Лендинг и документация (структура)

Цель страницы (или раздела на `registry.skpkg.org` / отдельный сайт — решает board с FE): **за 30 секунд** понять продукт, **за 5 минут** — установить CLI и поставить первый skill.

Рекомендуемые блоки:

1. **Hero:** продукт + CTA («Установить CLI», «Документация API»).
2. **Как это работает:** диаграмма registry → CLI → `skills.lock` → каталог `.skillget/`.
3. **Быстрый старт:** `go install` или бинарь релиза + `SKILLGET_REGISTRY_URL` + пример `search` / `install`.
4. **Доверие:** лицензия, ссылка на org, roadmap в Issues (без обещаний SLA до публичного релиза).
5. **Для авторов skills:** как опубликовать (ссылка на контракт registry / гайд).
6. **Футер:** GitHub org, статус сервиса (когда появится), политика приватности (если собираем аналитику).

Доки в репозиториях должны **дублировать минимум** (один источник правды — либо сайт, либо `README` + `docs/`), чтобы не расходились версии команд.

## 3. Северная звезда и воронка метрик

| Горизонт | Метрика (North Star / прокси) | Зачем |
|----------|-------------------------------|--------|
| 12–24 мес | **GitHub stars** суммарно по ключевым публичным репозиториям org (ориентир board: **10k** как северная звезда, не как KPI квартала) | Охват и доверие open-source. |
| Еженедельно | **Релизы:** теги/релизы на `cli`, `registry`, `skillget-manager` | Предсказуемость для ранних адоптеров. |
| Еженедельно | **Клоны / visitors** (GitHub Insights) по главным репо | Интерес до конверсии в stars. |
| Еженедельно | **Forks** и **PR извне** | Сообщество и вклад. |
| Еженедельно | **Упоминания:** ручной учёт + поиск по GitHub/Twitter/Discord/RU чаты (без автоспама) | Качество охвата важнее количества. |

**Дашборд для board (минимум):** таблица или документ раз в неделю: stars по репо, число релизов за неделю, 1–3 ссылки на лучшие внешние упоминания, блок «что отпустили» (anti-goals).

## 4. Рост без спама (обязательные правила)

- **Никаких** массовых однотипных комментариев в чужих issues, «star-for-star», ботов и покупных накруток — риск бана org и потери репутации.
- **Контент вместо шума:** релиз-ноты с миграциями, мини-гайды, 1 качественный пост там, где уже есть аудитория (HN, Reddit, профильные RU/EN чаты) — по одному сообщению на канал на релиз, не чаще.
- **Developer experience:** быстрый `README`, исправление «первого запуска за 5 минут» снижает отток сильнее, чем реклама.
- **Со-позиционирование:** интеграции и примеры с популярными агентами/IDE — через **доку и примеры**, не через тегание maintainers пачками.
- Координация с FE: отдельные подзадачи в Paperclip с копируемыми текстами hero/CTA и списком страниц — **без** @-mentions, если нет блокера.
